# 已落实的整合取舍

2026-11-06。用户要求保留原成熟界面、使用官方 Super Agent 源码并统一现有记忆。本阶段据此将默认路径调整为原 App → 原消息服务 → 官方 Super Agent → DSH。当前实现、适配限制和数据目录见 [架构说明](personbot-architecture-current.zh-CN.md)。

| 能力 | 负责方 | 原因 |
|---|---|---|
| 界面、bot/thread、消息展示、认证、配对设施 | 原 OpenMausBot | 保留成熟产品入口和已有用户数据 |
| 模型和工具循环、原生会话、压缩 | DSH | 使用原生能力，避免按旧引擎逐一适配上下文 |
| 路由、Ticket/Assignment、worker、任务报告、Effects/Outbox | 固定官方 Super Agent 核心 | 直接加载官方源码，适配个人部署和原消息来源 |
| 用户事实、偏好、专题、可见历史召回、记忆维护 | 原记忆服务 | 已有编辑、来源、日志和遗忘规则，无需另建权威事实库 |
| 身份映射、请求授权、审批/任务投影、进程恢复 | 托管网关与原产品适配层 | 独立于输入框管理后台生命周期，不另建任务判定循环 |
| 共享目录写租约、模型槽和入场额度 | 宿主协调器 | 跨会话、跨网关约束相同托管资源 |
| 实际调用 token、费用与归属 | 原用量账本 | 主助手、worker 和记忆维护归集到已有统计入口 |

记忆统一采取共享访问接口、来源标注和相同授权边界。事实、历史引用和任务资料各自保留权威来源。读写 RPC 绑定真实 request、用户消息、Agent 角色和授权版本；worker 默认只读，候选提交主助手，不能用自己的输出证明用户事实。`remember` 保存有证据的准确原陈述；`forget` 先验证当前用户明确要求遗忘准确目标，再清理原笔记并抑制召回和学回。历史日志继续按原留存规则存在。

原有记忆界面和原生工具修改相同的 MEMORY.md、专题文件和 journal。原 memoryUpkeep 通过无工具 DSH 文本生成端口运行。完整设计与精确限制见 [记忆设计](personbot-memory-design.zh-CN.md)。

官方 `src/core/memory.ts` 是领域仓储的内存实现，不是应该替换个人事实服务的产品记忆。DSH Session 也不是个人事实库；把 Session、任务状态和个人笔记视为同一个“记忆”概念，会再次形成双重写入和冲突。

输入轮次只控制当前输入框。官方持久任务继续拥有执行、等待和结束语义，审批请求独立绑定具体 request/ticket/工具调用。原卡片和任务通知使用持久来源投影，不能因另一轮输入开始而丢失仍有效的审批，也不能用旧审批批准新工具调用。Stop 有请求、单任务和会话全部三个明确范围。

同一线程的新消息仍可能由官方 Intake/followupOwners 交给已有任务，等待 worker handback；没有承诺同线程所有输入独立并行。独立线程或 context 可以分别调度，仍受宿主总资源限制。

上下文固定工作目录。目录变化建立新的 workspace context，并保留原目录中的后台工作；消息编辑/回退退出旧分支，撤销其后续投影和授权。后台恢复调度只扫描持久待办、遵守宿主资源与退避并唤醒官方 Runtime，具体任务仍由官方核心恢复。空闲回收检查任务、审批与投递，不仅检查输入框。

短期文件协调采用保守的共享写租约，覆盖参与同一协调器的托管 worker 执行和测试窗口、主助手变更工具、同一仓库及父子目录。它没有实现每任务独立文件视图或自动合并，也不协调用户和外部程序的手工文件操作。

活动写窗口在进程/宿主异常死亡或强制关闭时转为持久目录隔离；新的重叠写入暂停，重启不会自动清除。原设置复用确认对话框，由 owner/admin 核查外部进程和文件后明确解除，不向 Agent 提供此工具。这个机制保留“不确定是否仍有副作用”的状态，不把未知 PID 当作已结束证明，也不宣称工具没有孤儿或副作用恰好一次。

用量使用实际原生调用 ID 归集原账本，未知 USD 为空且明确计数，原每输入占位用量停用。模型并发、累计调用/token/已知费用限制与原月度预算分别检查；不把子进程数量当模型并发上限，也不把未知价格当零费用。账本与 Store 辅助累计不是一个跨存储事务，准确恢复以账本为依据。

单任务用量按原账本的完整身份汇总独占部分，包括缓存写入；同一上下文中主路由等未分配给任务的共享开销单列，明确不属于任务独占用量，不能按任务重复相加。各部分的已知费用与含未定价的完整总额分开。原设置显示模型槽、排队、token、额度、未定价和写隔离状态，可手动刷新。

早期独立界面、自有 supervisor 和 personal.sqlite 作为实验代码保留，不在官方模式运行，也不静默删除其数据。上一阶段的取舍分析保存在 [历史边界文档](archive/personbot-integration-boundaries-before-official.zh-CN.md)。

后端能力清单在原模型设置中展示，明确当前 DSH profile 未支持的原 Connected Apps、电脑工具、旧自动化、插件安装器和外部网关。原入口与连接记录保留，不等于执行能力已经迁移。

尚未完成的能力包括：每任务 worktree 与明确合并、非 Git 产物交付、一键配套备份及恢复校验、外部 DSH 网关、App 插件安装器、全部 Connected Apps/电脑工具挂载、旧自有任务数据迁移、真实账号/手机/桌面安装包验收。具体分阶段计划、升级契约和本轮变更边界见[加固设计](personbot-review-hardening.zh-CN.md)。[上次集成记录](verification/personbot-official-superagent-2026-11-06.md)保留其原有实测范围，不替代本轮加固的最终验证。
