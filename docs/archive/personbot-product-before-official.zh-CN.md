# Personbot 使用说明

Personbot 是这份源码的默认个人工作台。对话、工具和子 Agent 使用同一套 dsh 原生执行循环；任务目标、验收、记忆、产物、定时和外部渠道由 Personbot 持久管理。打开 App 后直接进入 Personbot。

当前部署方式、外部 DSH 网关、插件管理和手机兼容性的实现边界见 [当前架构说明](personbot-architecture-current.zh-CN.md)。

## 启动

在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm personbot:start
```

启动器会在需要时构建前端，然后用一个本机端口提供界面和服务，默认地址为 `http://127.0.0.1:8799`。首次使用，在 **模型设置** 中填写 DeepSeek API key，保存后创建会话。依赖保持仓库锁定版本；本次验收环境为 macOS arm64、Node.js 26.10.0、pnpm 10.33.0、dsh 0.2.2-rc.1。

无需 API key 的独立体验：

```sh
pnpm personbot:start --demo
```

这会启动真实 dsh 进程和确定性演示模型，使用临时 HOME、数据目录和工作区。在新会话中发送 `echo hello` 体验完整消息管线，发送 `approve` 体验工具审批，发送 `question` 体验问题卡片。在 **长期任务** 中创建目标为 `task-review`、完成条件为 `检查演示报告` 的任务，可以体验独立 worker、报告和人工验收。演示模型只识别受控指令，不能处理一般模型请求。Ctrl-C 停止启动器拥有的服务和运行时，并删除演示数据。

| 参数 | 用途 |
|---|---|
| `--port 8809` | 指定本机端口 |
| `--home /absolute/path` | 指定 Personbot 持久目录 |
| `--workspace /absolute/path` | 指定新会话默认工作区 |
| `--build` | 强制重新构建前端 |
| `--skip-build` | 使用已有 `dist`，不存在时明确报错 |
| `--demo` | 临时、隔离的确定性演示；不能与 home/workspace 参数组合 |

正常模式默认 home 为 `~/.personbot`，默认 workspace 为该 home 下的 `workspace`。启动器还使用旧 App 的数据目录读取历史和执行现有认证；若同一旧工作区正由另一个服务占用，应先停止那个服务。App 与 CLI 共享同一 Personbot home 时，也只能有一个运行时拥有锁。需要同时运行两个环境时，分别指定 `OMB_DATA_DIR` 和 `--home`，避免共享数据。

## 工作台

| 导航 | 可以做什么 |
|---|---|
| 对话 | 新建、切换和继续会话；查看流式回答与工具记录；批准或拒绝操作；回答问题；停止执行 |
| 长期任务 | 创建独立 worker；查看目标和完成条件；补充要求；暂停、继续、终止；验收或要求修改 |
| 项目与记忆 | 配置本机项目目录、角色说明和确认后的个人/项目记忆 |
| 产物 | 发布工作区已有文件，预览和下载持久保存的版本 |
| 事件与渠道 | 配置 Webhook 来源、线程订阅、定时触发和结果回调；处理结果未知的投递 |
| 旧历史 | 浏览原有直接对话、群组及任务历史，确认上下文后导入新 dsh 会话 |
| 模型设置 | 保存或清除 API key、选择模型，查看当前配置和重启要求 |

切换设置或旧历史页面会保留当前对话草稿。手机通过左上角导航按钮切换页面。长期任务拥有独立的原生会话，主对话可以继续；worker 提交报告后进入人工验收，模型的最后一句回复不会自动把业务任务标为完成。

项目、角色、记忆、任务状态、执行树停止、产物与事件的详细语义见 [运行时说明](personbot-runtime.zh-CN.md)。

## 模型与凭据

当前产品设置支持已锁定 dsh 发布包中的官方 DeepSeek provider，模型为 `deepseek-flash` 和 `deepseek-v4-pro`。保存 API key 后，界面只显示是否已配置，不读回原文。省略 key 表示保留已有值；清除需要显式选择。设置以原子写入方式保存在 `<home>/runtime/settings.json`，目录权限为 `0700`，文件为 `0600`。

如果启动服务的环境已有 `DEEPSEEK_API_KEY`，它优先于保存值；界面会显示凭据来自环境，并拒绝覆盖或清除环境中的值。请在启动服务的环境修改后重启。

运行时已经启动后，修改实际生效的模型或凭据会显示 **需要重启**。先处理或暂停正在进行的任务，用 Ctrl-C 关闭服务，再运行原启动命令。系统不会为了应用设置而静默中断工作。修改只影响之后启动的运行时，既有 Session 的身份和历史保持连续。

## 从旧系统继续工作

进入 **旧历史**，选择一个对话，可以分页阅读原记录。点击 **导入并继续**，明确填写新的目标和已经核实的进展，再选择是否导入角色说明和有效的本机项目目录。确认后创建一个新的 dsh 原生会话；请求重试复用同一导入回执，不重复创建会话。

导入使用最近的、有大小上限的历史文本作为不可信参考材料，以人工确认的目标和进展为准。原引擎私有会话游标、凭据、工具权限和旧自动化不会迁移。附件只展示已保存的元数据，凭据及登录记录的正文会隐藏；这不等于对任意自然语言文本做完整秘密识别。

旧记录不因导入而改写。主模式不运行旧引擎、旧 Chief、旧自动化与旧 Webhook；旧执行写接口和控制连接被拒绝。需要的定时和渠道在 Personbot 中重新配置，避免相同工作被两个系统同时执行。

需要返回旧界面时，先停止 Personbot，并处理可能与旧自动化重复的 Personbot 来源或定时，再显式启动：

```sh
PERSONBOT_PRIMARY=0 pnpm dev:server
```

另一个终端执行 `pnpm dev`。`PERSONBOT_ENABLED=0` 可以同时关闭 Personbot 接口。hosted/Cloud 和打包版没有自动切换为新的个人主模式。

## 数据与当前交付边界

Personbot home 包含原生历史、业务 SQLite、设置、导入回执、任务工作区和产物；旧 App 备份不会自动包含位于其数据目录之外的 home。备份前停止对应服务，保存完整 home；Git worktree 还依赖来源仓库。

本阶段交付可从源码启动的本机 App，已验证实际 dsh、真实浏览器、重启和隔离演示。尚未验收桌面安装包、Linux/Windows 发行、真实模型效果或第三方真实账号。长期任务和事件历史的大规模归档、供应商专属渠道签名和插件安装管理也不在当前交付范围。验收证据见 [W6 记录](verification/personbot-product-2026-11-06.md)。
