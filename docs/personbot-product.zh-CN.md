# 原界面 + 官方 Super Agent 使用说明

当前默认个人源码模式保留原 OpenMausBot 界面，用官方 Super Agent 管理任务、DSH 执行模型与工具。长期记忆继续使用原 bot 的文件、检索、编辑、变更日志和遗忘规则。

## 启动

```sh
pnpm install --frozen-lockfile
pnpm personbot:start
```

启动器按需执行 `pnpm personbot:build`，检查原产品与官方运行时的类型后，把原界面构建到专用 `dist-personbot` 目录并从该目录提供服务，默认使用 `http://127.0.0.1:8799`。也可以先单独运行 `pnpm personbot:build`。在原设置的 AI/连接区域配置 DeepSeek API key，然后使用原侧栏选择 bot、新建会话并发消息。也可以在服务启动环境提供 `DEEPSEEK_API_KEY`。

无账号隔离演示：

```sh
pnpm personbot:start --demo
```

演示使用真实官方运行时和 DSH，模型由确定性 fixture 代替，不访问外部模型。以下输入只属于演示语言，不是正常模型的固定命令格式：

| 输入 | 演示内容 |
|---|---|
| `echo hello` | 原聊天发送、官方主 Session 路由和正式回复 |
| `task write official-proof.txt` | 官方 Ticket、worker 和 DSH 原生文件工具 |
| `memory jasmine tea` | 查询当前 bot 的原记忆及有权限的历史 |
| `remember The person prefers jasmine tea.` | 使用用户本句话作为证据，写回原记忆 |
| `forget jasmine tea` | 原笔记遗忘与召回抑制 |
| `task approval` | 原聊天审批卡与原生审批服务 |
| `task question` | 原聊天问题卡 |
| `task attention`，然后 `attention answer Mars` | 官方任务追问、补充需求与同一任务的最终结果 |
| `task hold` | 长时间执行，用原 Stop 按钮停止 |

Ctrl-C 关闭启动器拥有的服务和运行时，删除隔离演示数据。正常模式的数据会保留。

## 日常操作

- 对话、会话切换和历史展示仍在原界面。普通继续使用 DSH 原生上下文；编辑/回退消息会换用独立上下文。
- bot 的原记忆管理页仍可编辑 `MEMORY.md` 与专题文件、查看变更日志和维护状态。Agent 的记忆工具读写的是这些相同文件。
- 工具审批和问题显示为原聊天卡片，独立绑定原任务和工具调用。任务让出输入框后，仍有效的后台审批可以继续展示和回答；它不会借用新一轮输入的授权。已经失效的旧卡不能批准恢复后的新工具请求。
- 原 Stop 在有明确当前请求时停止该请求的工作。后端还提供停止单个任务、停止会话全部任务的管理接口，范围见[运行时说明](personbot-runtime.zh-CN.md)；当前没有新增完整的后台任务管理工作台。
- 改变 bot/会话工作目录后，后续输入使用新的原生 context，并显示执行目录。已经在旧目录工作的任务继续绑定旧目录；消息编辑/回退则退出旧分支，不恢复它的执行权限。
- 服务启动会唤醒需要恢复的后台任务和待投递结果，按资源上限和退避继续；无需再发一条消息来激活。运行中的服务是持续工作的前提，退出整个服务后不会在关机状态继续执行。
- 原 AI/连接区域保存模型和 API key。key 只写入，不回显；环境凭据优先。活动会话不静默切换模型或凭据；按提示停止活动工作并重启服务。
- 同一区域显示后端能力清单。原 Connected Apps 的连接记录、浏览器/电脑页及自动化入口存在，不代表它们已经挂到当前 DSH profile；以清单中的支持状态和原因判断。

主助手有明确来源和当前授权时才能修改记忆；worker 默认只读，需要写入时向主助手提出候选。“忘记 X”还必须在当前真实用户消息中明确要求遗忘准确的 X，普通总结请求不能授权删除。需要改写个人事实时，先明确确认新表述。原管理页的手动编辑继续使用原来的文件冲突与日志规则。

同一线程的新消息可能由官方运行时作为当前任务的补充，等待 worker 交还。旧任务的审批仍能回答；独立审批不意味着该线程每条输入都并行执行。需要分别推进的工作可使用独立线程或上下文。

当前模型选项取决于锁定的 DSH provider；默认配置为 `deepseek-official / deepseek-flash`。本次隔离验收不证明真实模型回答质量或真实账号工具已可用。

## 参数与数据

| 参数 | 用途 |
|---|---|
| `--port 8809` | 本机端口 |
| `--home /absolute/path` | 官方运行时的持久 home |
| `--workspace /absolute/path` | 默认本机工作目录；bot/会话已有目录优先 |
| `--build` | 强制执行 `personbot:build`，构建到 `dist-personbot` |
| `--skip-build` | 只使用已有 `dist-personbot`；该目录缺失时明确报错 |
| `--demo` | 临时隔离演示，不与 home/workspace 参数组合 |

原 bot、消息、记忆在 OpenMausBot 数据目录。原生 Session、官方任务库和绑定在 Personbot home，默认 `~/.personbot`。

同一用户的托管网关还默认共享 `~/.personbot-host/host-resources.sqlite`，其中保存模型槽、目录租约、异常写入隔离、额度策略和累计使用量。隔离演示使用自己的临时资源目录。它不保存个人记忆或模型凭据。

## 并发、费用与停止

服务默认最多持有 8 个子运行时；实际模型调用还受独立的宿主级上限限制，默认同时 4 个。主助手、worker 和记忆维护共同占用这些模型槽。共享同一目录或同一 Git 仓库的写工作还会排队，保守覆盖 worker 的执行与测试窗口。

正常服务启动可使用下列环境设置；共享宿主目录的所有网关需要相同策略。累计额度保留在宿主数据库，不随新会话或服务重启自动重置。

| 环境变量 | 含义 |
|---|---|
| `PERSONBOT_MAX_MODEL_CALLS` | 同时入场的模型调用上限，默认 4 |
| `PERSONBOT_MAX_MODEL_REQUESTS` | 可选，累计模型调用次数上限 |
| `PERSONBOT_MAX_TOKENS` | 可选，累计实际输入与输出 token 上限 |
| `PERSONBOT_MAX_COST_USD` | 可选，可验证的累计美元额度；出现未定价调用后暂停新的模型调用 |

达到额度后拒绝新调用，已经入场的调用可以完成，因此 token/费用总量可能在该批调用结束后超过阈值。原产品配置的月度预算也会在每次 native 模型入场检查。改变共享策略前应停止所有拥有该资源目录的服务。

原用量页面和 CSV 读取实际主助手、worker 和维护调用，按原生调用 ID 去重。未知费用显示为未定价，不能解释成零消费；已知费用合计在存在未定价调用时只是部分合计。后台任务查询与资源查询可通过[原认证下的管理 API](personbot-runtime.zh-CN.md)查看。原账本是费用权威，Store 的辅助累计计数仍存在单独存储的崩溃重建边界。

原模型设置增加了紧凑的运行时状态：模型槽占用、排队、token、额度和未定价次数，打开时读取并可手动刷新。单任务用量 API 从原账本按 bot/thread/context/ticket 精确汇总独占调用、缓存读写和费用；另列同一上下文的未分配共享开销，包括主助手路由。共享部分不计入该任务，也不能在多个任务间重复相加。两部分各自保留完整费用与已知部分，未定价时完整费用为空；系统不凭时间猜测分摊。

## 异常写入隔离

活动写窗口中的原生进程或宿主异常退出、被强制关闭时，相关目录会进入持久写入隔离。重启不会自动解除，新的重叠写任务暂停；不需要写窗口的模型读取可继续。系统不通过猜测未知外部工具 PID 来假定它已经退出，也不保证任意原生工具没有留下孤儿进程。

在原模型设置的运行时状态中查看目录和原因，先确认相关外部工具已经停止并检查文件状态，再选择“检查后解除隔离”。原确认框会再次说明影响；只有明确确认才调用带 `external-processes-reviewed` 声明的原认证管理接口。解除后允许后续写入重新入场，任务是否继续取决于官方任务状态。

这个入口用于本人或管理员核查后的保守恢复，不是自动证明文件正确、回滚外部副作用或保证工具恰好执行一次。它没有注册成 Agent 工具。

## 备份、恢复与版本

目前没有把三处数据合为一次操作的备份/恢复入口。需要停止所有共享宿主协调目录的服务，再分别保存原 OpenMausBot 数据目录、Personbot home 和宿主资源目录。不要只备份原 App 后假定 DSH Session 和官方任务也已包含；也不要复制运行中的 SQLite/WAL 文件作为完整快照。

恢复时使用同一固定代码与依赖版本，先在隔离副本核对数据、任务和授权，再启动正式服务。目录协调是任务执行租约，不是文件版本隔离；每任务 worktree、合并确认和非 Git 产物交付仍未提供。

旧阶段的独立 Personbot 工作台、自有 supervisor 和 `personal.sqlite` 不再作为默认路径运行，已有实验数据不自动删除或静默合并。旧阶段说明在 [历史文档](archive/personbot-product-before-official.zh-CN.md)。外部 DSH 网关、插件安装管理和原工具能力迁移的边界见 [当前架构](personbot-architecture-current.zh-CN.md)。

源码核对环境为 macOS arm64、Node.js 26.10.0、pnpm 10.33.0、DSH 0.2.2-rc.1。上次集成证据见[官方接入验收](verification/personbot-official-superagent-2026-11-06.md)；本轮加固与尚未完成的能力见[加固设计](personbot-review-hardening.zh-CN.md)。真实模型账号质量、桌面安装包、其他操作系统和真实手机配对仍需分别验证，不能从本机 fixture 结果推导。
