# 后台任务生命周期与权限加固

更新日期：2026-11-06。本文解释本轮代码 review 对应的实现与保留边界。运行主链继续使用原 OpenMausBot 产品入口、固定上游 Super Agent 核心和 DSH，不引入另一套任务判定循环。本文按源码描述设计，不把上一次验收结果当成本轮重新运行的证明。

## 数据权威继续保留

原产品保存用户、权限、bot/thread 和可见消息；DSH 保存实际模型和工具上下文；官方 Super Agent 保存任务、分配、报告和 Outbox；原记忆服务保存个人事实。宿主新增的 task/decision/usage 投影服务于进程恢复、授权和原产品展示，不能替代官方任务状态或创建另一份个人记忆。

| review 问题 | 当前实现位置 | 实现边界 |
|---|---|---|
| 后台审批依赖当前输入 | driver、`superagent-projection.ts`、网关 decision 表 | 独立审批身份、来源投影、准确回答与失效 |
| 记忆未绑定 request/caller | plugin、网关授权、原记忆桥接 | worker 只读；master 写入验证来源、版本与操作证据 |
| cwd 变化复用旧进程 | driver workspace context、网关固定目录 | 目录变化开新 context，原后台任务保留原目录 |
| 多 worker 共用文件状态 | `host-resources.ts` 与 native 执行钩子 | 同仓库/重叠目录的托管写窗口互斥 |
| 恢复需要新输入触发 | 网关持久恢复标记、扫描与退避 | 自动唤醒官方 Runtime；活动快照决定回收 |
| 模型资源与用量未归集 | 宿主模型槽/额度、`superagent-usage.ts`、原账本 | 实际调用统一入场与记账，未知费用保持未定价 |

完整模块说明见[运行时](personbot-runtime.zh-CN.md)，个人事实规则见[记忆设计](personbot-memory-design.zh-CN.md)。

## 三种生命周期

| 生命周期 | 权威身份 | 结束代表什么 |
|---|---|---|
| 输入轮次 | 原 requestId、原用户 messageId | 当前输入框释放，可以发送下一条消息 |
| 持久任务 | 官方 ticketId、assignment 与原 context | 工作完成、关闭、停止或等待；可越过多个输入轮次 |
| 审批/问题 | decisionId、request、ticket、agent、callId、授权版本、原生进程拥有者 | 具体工具收到回答、被取消或失效 |

后台事件不使用正在输入的新 request 冒充旧任务的来源。原产品投影重新检查 bot/thread、当前活动分支和原用户消息，以稳定 decisionId 或任务状态去重；卡片保留 ticket/工具身份。输入轮次完成不会自动删除仍有效的 pending decision。

同一线程后续消息仍可由官方 Intake/followupOwners 交给当前任务作为补充，因此可能等待 worker 交还。这与审批独立有效并不冲突。没有承诺同线程所有输入独立并行；独立线程和 context 可分别执行，受相同宿主资源限制。

审批回答必须同时符合：decision 仍 pending、所属活动分支未退出、原授权版本未撤销、任务未结束或被停止、实际原生进程仍持有这个 pending 调用。原生进程退出后，旧 decisionId 过期；官方恢复若再次请求审批，则创建新的 decisionId。重启不意味着旧卡获得批准新工具的能力。

停止范围明确为：

- `request`：停止消费该原输入的工作，撤销对应请求授权。
- `task`：停止准确 ticket，撤销该任务的审批与记忆写入资格。
- `conversation`：停止该 bot/thread 下全部活动上下文，包括目录切换前保留的后台工作。

原 Stop 能确定 request 时使用 request 范围。后端管理 API 分别提供单任务和会话全部停止；本轮没有增加新的后台任务工作台。原问题卡、审批卡和状态消息仍是主要交互入口。

删除 bot、单删/批删线程和切换消息分支会在产品记录变更前等待原生撤销，覆盖该线程全部工作目录上下文。紧急 Full→Ask 降权同样停止后台任务，不以输入框 busy 为前提。内部同步删除另有 Store 变更兜底；原生撤销先同步提交授权版本、审批、任务和恢复标记，再等待关闭已有子进程。永久撤销的 context 不会因为并发输入重新激活。

请求级和任务级 Stop 另行封锁已经排队的旧路由候选，持久化 `admission_revoked`，并保留其他仍有效任务的读取、审批和报告处理。主助手处理新路由与消费 worker 报告由实际原生消息类型区分，模型参数不能选择这项身份。停止也撤销相关 executor-completed 任务的可恢复委托；只检查当前 open 任务会遗漏这类任务留下的订阅。历史上收到过某条消息不能继续让旧任务占有已经交回的新输入。

原生任务的终止状态可以更新原状态消息；停止后的新审批和活动事件仍被拒绝。服务启动时重放的审批失效事件也会直接更新原卡片，不要求 driver 内存中还保留上一进程的 decision。

## 记忆授权

native 工具注册时取得真实 Agent 身份，模型参数不能选择 Bot 或把 worker 变成 master。记忆 RPC 携带：

```text
bindingId
  → botId / threadId / contextId
caller
  → requestId / sourceMessageId / authorizationVersion
  → agentId / role / ticketId
```

网关按持久请求验证并重建来源与版本，原记忆端口再次检查当前可见性、作者和宿主授权。写入需要 `canWrite(binding, request) === true`；生产宿主还调用 `gateway.authorizeMemory` 重查实际已初始化的 master、原来源、版本和写入撤销状态。没有显式写授权时全部写操作拒绝。读取继续遵守原 audience/profile 边界。

worker 默认使用读取工具，可以通过 `memory_propose` 把候选交给官方主助手。候选仍是不受信任务材料，不触发个人事实写入。真正的 `remember` 要保留真实用户陈述的原文；存在一条引用不能证明任意改写符合原意。

`forget` 要求原用户消息明确指示遗忘准确的 passage。无关总结请求、引用中的命令、否定“不要忘记”、问题、假设和待确认说法不能产生删除或墓碑；也不能把 `jasmine tea` 扩大成 `tea`。当前采用保守中英文直接命令匹配，未覆盖的含糊说法需要用户明确重述。

Stop 使相关请求版本或任务授权失效，新输入也不能把旧 worker 的读权限升级为写权限。全部记忆检查在任何笔记、About me、journal 或墓碑变更之前完成。普通遗忘仍不物理删除聊天、journal、官方任务或 DSH 历史。

## 目录上下文与文件协调

每个 context 的 cwd 是创建时固定的真实路径，并进入进程 fingerprint。符号链接别名折算为同一路径。后续请求实际 cwd 变化时，driver 新建 workspace context，显示新执行目录；网关拒绝直接修改旧 context 的 cwd。

workspace 转换保留旧后台任务及原目录。branch 转换用于消息编辑/回退，退出旧活动分支的投影、恢复与权限。这两个转换不能混用，否则目录变化会意外取消工作，或旧分支会继续产生副作用。

宿主协调器在共享 SQLite 事务中分配写租约，作用范围是：

- Git 目录归到所在仓库根目录，避免同仓库不同子目录的测试与编辑并行穿插。
- 非 Git 目录规范为真实路径，同时检查父子路径重叠。
- 不同 bot/thread/context 和不同托管网关共用同一资源目录时，参与相同的写协调。
- 当前保守覆盖 worker 的模型、工具、测试及仍活动的后台工作窗口；主助手的原生变更工具也取得租约。

这会牺牲部分 worker 并发，避免在没有文件隔离时过早声称“只读分析”与变更互不影响。它只协调参与协议的托管工作和已声明目录，不是 OS 文件沙箱，也不阻止用户、编辑器或其他外部程序修改文件。

每任务 Git worktree、显式合并/冲突解决、非 Git 任务输出目录及交付步骤仍未实现。后续应先提供独立文件状态与合并前验证，再提高写并发。

## 异常写窗口的持久隔离

活动写窗口的原生进程或宿主异常死亡、写窗口尚未安全结束即被强制关闭时，相关目录进入持久 workspace quarantine。未取得租约的排队请求退出不需要据此隔离目录；正常完整释放仍按原流程进行。

隔离覆盖同一仓库及重叠目录，阻止后来的写窗口入场，并在服务或协调器重启后保留。不需要写窗口的模型读取不因此被阻断；保守取得整个写窗口的 worker 仍可能等待。系统不凭猜测未知外部工具 PID 来自动清除不确定状态，也不把收到一个进程退出事件当作所有外部副作用已结束的证明。

原模型设置显示被隔离的工作目录和原因，复用原确认对话框。owner/admin 先检查相关外部工具是否结束及文件状态，再明确确认解除。管理接口严格要求：

```json
{"acknowledge":"external-processes-reviewed"}
```

字段必须准确且没有额外字段，原 owner/admin 身份和会话仍须有效。解除隔离没有注册成 Agent 工具。解除后只重新允许写入入场，具体任务是否继续仍由官方任务状态决定。

这个机制是保守暂停加本人核查，不保证任意原生工具没有孤儿进程、不自动修复文件，也不证明任意副作用跨崩溃恰好执行一次。后续仍需按工具类型完善可靠进程归属、产物验证和独立文件状态。

## 自动恢复与空闲回收

宿主启动先连接后台事件消费者，再启动网关。网关从持久数据库识别需要恢复的活动绑定，包括未完成入场、未结束任务、pending decision、未确认投递和 Stop 意图，按资源限制与退避唤醒对应官方 Runtime。恢复具体 Session、任务和效果仍由官方实现完成。

没有待办的历史绑定不全部启动。提交在真正入场前因配置或容量被拒绝时，会保留拒绝/撤销状态，不能在之后的后台扫描中偷偷执行。分支退出的绑定也没有恢复资格。

启动同时检查旧版本已经持久化的活动绑定，即使旧 schema 没有完整的恢复标记，也不会恢复已删除的用户归属、退出的分支或当前已撤销的 Full 权限。原生任务还在而新宿主任务投影为空时，恢复钩子先从官方任务库重建准确投影，再确认停止来源，保持严格的反向 RPC 授权检查。恢复检查撤销旧游标后，下一条真实用户输入创建新 context；不会重新激活旧身份，也不会因为保留一个已失效游标而永久拒绝续聊。

回收同时检查输入 busy、官方活动快照、未结束任务、待审批及待投递。输入框空闲与官方任务结束不是同一个状态。取消、崩溃和退出按精确进程与租约拥有者处理，不按进程名称释放其他工作的资源。

自动恢复需要宿主服务持续运行，不包含系统登录服务安装、机器断电时执行或远程永续运行保证。任务恢复和 Outbox 重试不等于任意外部工具副作用的跨进程恰好一次保证。

## 总并发、额度和原费用账本

默认最多 8 个托管子运行时，实际模型调用另受宿主级模型槽控制，默认同时 4 个。主助手、worker 和无工具记忆维护都在调用前取得模型槽；写租约、模型槽和预算分别管理。

生产默认共享 `~/.personbot-host/host-resources.sqlite`，fixture 使用隔离资源目录。共享策略必须一致，改变策略前应停止所有拥有者。累计模型调用数、输入/输出 token 和可验证美元额度保留在该数据库，不随会话或服务重启重置。正常服务的环境配置见[使用说明](personbot-product.zh-CN.md)。

限额在模型入场时检查。达到调用/token/费用阈值后，后续调用拒绝入场；已经开始的调用可以结束，其实际结果可能使累计 token 或费用超过阈值。设置美元限额时遇到未定价调用，后续调用也暂停，不能把未知价格解释为零。原产品月度预算在 native 入场前、等待后重新检查。

取得共享槽以及完成异步预算检查后，还会重查分支、来源和准确任务的撤销状态。一个等待模型槽的旧调用不能因为槽后来空出而越过期间发生的 Stop。

每次 native 调用生成稳定 usageId，网关先保留待投影记录，原 `usage/YYYY-MM.jsonl` 写入并同步后才确认。主助手、worker、维护分别保留角色、request、Agent 和 ticket 身份。原用量页面、分组统计与 CSV 直接读取这些记录；原每输入轮次占位记账在官方模式停用。

未知 USD 使用 null，并显示未定价数量。存在未定价调用时，已知美元合计只是部分合计。不会为展示完整数字编造价格。按 token、调用数和已报告价格所施加的限制不能证明实际供应商账单的最终总额。

已经入场但异常中断、尚未返回 usage 的模型调用，宿主保留未报告数量并计入未定价情况。没有报告不能解释为零 token 或零消费；不能为填满报表编造用量。

原账本通过 usageId 防止跨重启重复写入，Store 的辅助累计只在新记录时更新。两处存储不是一个原子事务；崩溃发生在账本已同步、Store 尚未更新之间时，辅助投影可能滞后。准确查询以原账本为准，完整计数修复应从账本重建。

任务用量接口直接重算原账本，将两种归属明确分开：

| 部分 | 归属标记与筛选 | 如何解释 |
|---|---|---|
| 顶层任务用量 | `attribution: "ticket-exclusive"`；严格匹配 bot/thread/context/ticket | 只有明确归属此 ticket 的调用 |
| `shared` 共享开销 | `attribution: "context-unallocated"`、`exclusive: false`、`includedInTaskTotal: false`；同一 bot/thread/context 中没有 ticket 的记录 | 包含主助手路由；没有分配给某个 ticket，不计入顶层任务数字 |

两部分都返回已落盘调用数、输入/输出/缓存读取/缓存写入 token、knownCostUsd、unpricedCalls 和 costUsd。各自只要有未定价记录，完整 costUsd 就为 null；没有记录也不显示为零费用。共享池保留 botId/threadId/contextId，可能涉及多个请求和多个任务；同一 context 的不同任务查询会展示相同共享池，调用方应按池身份去重，不能按任务重复相加，也不能把它当成每项任务的独占完整费用。系统不按照相近时间或一条输入产生几个 ticket 来猜测分摊。未报告用量的入场状态另见宿主资源。

## 管理入口与能力清单

所有新端点复用原认证，仅对有效 owner/admin 或本机 owner 提供：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/personbot/capabilities` | 支持状态和未支持原因 |
| `GET /api/personbot/tasks?threadId=<threadId>` | 可见活动分支的任务与审批投影 |
| `GET /api/personbot/tasks/<ticketId>/usage` | 原账本中任务独占用量与同 context 未分配共享开销，含缓存读写、已知费用和未定价数 |
| `GET /api/personbot/resources` | 模型活动/排队数、累计用量、未定价数和额度 |
| `POST /api/personbot/tasks/<ticketId>/stop` | 停止准确任务 |
| `POST /api/personbot/threads/<threadId>/stop` | 停止会话全部活动上下文 |
| `POST /api/personbot/workspaces/<id>/reconcile` | 原认证及明确核查声明后解除指定持久写入隔离 |

原模型设置读取能力清单和资源快照，展示当前 profile 的支持情况、模型槽/排队/token/额度/未定价及写隔离，打开时读取并可手动刷新。原 Connected Apps、电脑工具、自动化、插件安装器和外部网关的入口或连接记录保留不代表新运行时拥有这些能力；完整逐页禁用、工具选择与迁移仍应在各能力接入时覆盖。

## 备份与后续工作

本轮没有提供一键配套备份和恢复。当前仍需要停止所有共享协调器的服务，分别备份原产品数据、Personbot home 和宿主资源目录。单独原 App 导出不包含外部 Session、官方任务或宿主额度历史。

后续工作按可验收目标推进：

1. 为 Git 任务提供独立 worktree、交付差异、合并前检查和用户确认；非 Git 任务使用输出目录及明确交付步骤。
2. 提供一次操作的配套快照、版本清单与完整性校验；恢复到隔离位置验证原消息、任务、记忆、审批失效和额度历史，再切换正式服务。
3. 随原工具逐项迁移补齐能力入口控制与契约测试，再提供插件安装管理或外部网关连接器。
4. 分别验证真实模型账号、真实手机配对、发布版 companion、桌面安装包和其他操作系统。fixture 不替代这些验收。

## 上游升级

Super Agent 固定来源 commit 和 DSH 锁定依赖继续记录在[来源及补丁说明](../packages/personbot-superagent/UPSTREAM.md)。保留原 MIT 许可证、原始版本依据和本地行为补丁，不把研究原型描述为正式生产产品。

升级应作为单独变更：更新固定版本与锁文件，核对 native API/loader 兼容、持久 schema 和回退方案，然后重新运行请求/任务 Stop、审批身份与失效、Outbox 来源与重投、Session 自动恢复、记忆授权、目录/写租约及模型额度契约测试。先验证隔离数据迁移，再升级正式数据；未验证的持久格式降级不应静默进行。

最终发布记录应注明具体提交、实际执行的测试和仍未覆盖的范围。本设计文档不预填未执行的通过数字。
